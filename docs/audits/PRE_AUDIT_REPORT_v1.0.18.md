## 1. Executive Summary & Pre-Audit Scope

Prior to implementing the `v1.0.19b` upgrade specified in `humid1-audit-v1.0.19b.md` and the accompanying technical literature (`tech_docs.zip`), a comprehensive static, mathematical, and runtime pre-audit was performed on the `epd-font-v1.0.18-fixme.zip` baseline (`14` Python modules, `30` Windows `.bat` scripts, `20` declarative `.scheme.json` files, and `113` static `.ttf` assets).

The pre-audit evaluated six critical areas identified during `v1.0.18` bench testing:
1. Root causes of the `full-audit-build-distro` execution crash across the `10px–40px` (`step 2px`, `368`-strike) audit suite.
2. Root causes of the filled icon asset (`Tabler-Filled.ttf` / `humid1_icon_tabler_filled_*`, `Phosphor-Fill.ttf`, and `FontAwesome7-Solid.ttf`) sheet rendering failures.
3. Elimination of hardcoded partition size defaults (`3 Mbit` / `64 KB..8 MB` fallback table) in favor of explicit root hardware scheme files (`esp32s3-N8R8-hw_scheme.json` and `genaric_hw.json` / `generic_hw.json`) enforcing the single `3 MByte` (`3,145,728` bytes) partition specification with strict error validation.
4. Addition of explicit `"char_debug"` and `"sheet_debug"` boolean gates and redesign of `"pipeline": "all"` (plus `"all-debug"`) so every offered conversion method executes independently and outputs per-method inspection sheets and character blueprints for side-by-side comparison.
5. Upgrade of grayscale conversion to true sRGB-to-Linear luminance ($Y_{\text{lin}} = 0.2126 R_{\text{lin}} + 0.7152 G_{\text{lin}} + 0.0722 B_{\text{lin}}$) with configurable gamma contrast ($\gamma$), implementation of true Multi-Channel Signed Distance Field (`msdf`) per [Chlumsky/msdfgen](https://github.com/Chlumsky/msdfgen) alongside `mdf`, and implementation of three additional resolution-reduction conversion pipelines (`sdf-smoothstep`, `adf-biquadratic`, and `otsu-adaptive`) derived from the attached research papers and [Clément Bœsch's SDF anti-aliasing analysis](https://blog.pkh.me/p/44-perfecting-anti-aliasing-on-signed-distance-functions.html).
6. Removal of legacy dead code (`tools/fonts/humid1_bilevel_tuner.py` and deprecated CLI flags) and verification that zero `.docx` files exist in the repository.

## 3. Detailed Technical Analysis of Pre-Audit Findings

### 3.1 Root-Cause Analysis of the Full-Audit Crash (`PRE-19-01`)

During execution of `scripts/full-audit-build-distro/99_run_full_pipeline.bat` (`full_audit_distro.scheme.json`, which defines `23` font and icon strike groups across `16` even pixel sizes `10px..40px` = `368` strikes), three compounding defects caused the pipeline to crash:
1. **Unclosed `TTFont` File Descriptor Leak in Secondary Face Lookup (`humid1_ft_raster.py:768–775`)**:
   Inside `rasterize_font_strike()`, up to 6 fallback/secondary `.ttf` files (`NotoSans-Medium.ttf`, `NotoSansMath-Regular.ttf`, `IBMPlexSans-Medium.ttf`, `IBMPlexMath-Regular.ttf`, `IBMPlexSans-Regular.ttf`, `NotoSans-Regular.ttf`, or `FontAwesome7-Brands.ttf`) were opened via `open_ttfont_safe(sp, font_number=0)` on *every* strike without caching in `_TT_META_CACHE` or calling `s_tt.close()`. Across `368` strikes and `5` pipeline evaluations per strike (`1,840` calls), worker processes accumulated `11,040` open file handles, exceeding the Windows CRT `512`-file descriptor limit (`OSError: [Errno 24] Too many open files`) and crashing `ProcessPoolExecutor`.
2. **Windows `freetype-py` Shared Library Lookup (`humid1_ft_raster.py:356–363`)**:
   On Windows hosts where FreeType is installed via `pip install freetype-py` (`00_setup_env.bat`), the shared library (`libfreetype-6.dll` or `freetype.dll`) resides inside the `freetype` Python package directory rather than `C:\Windows\System32`. Calling `ctypes.util.find_library("freetype")` returned `None`, and `ctypes.CDLL("freetype.dll")` raised `FileNotFoundError` unless a system-wide DLL happened to be on `PATH`.
3. **Unbounded Character PNG Rendering & IPC Serialization Pressure**:
   Because `v1.0.18` lacked `char_debug` and `sheet_debug` boolean gates, `--workflow audit` in `02_build_fonts.bat` unconditionally rendered `44,000+` `1116x760` individual character blueprint PNGs (`inspect_chars/`) while returning all `GlyphStrike` objects across the multiprocessing pipe, and `99_run_full_pipeline.bat` executed that full pass three times.

### 3.2 Root-Cause Analysis of the Filled Icon Sheet Rendering Failure (`PRE-19-02`)

Inspection of `build/audit/inspect_pages/humid1_icon_tabler_filled_16.png` and `master_char_icon_map.png` reproduced the exact symptom reported by the user:
- `humid1_icon_tabler_filled_16.png` rendered an empty header banner (`PATCHED: 0/0`, `Glyphs: 0 (0 patched)`, `ROM: 120 B`) with zero icon cells, and `master_char_icon_map.png` displayed `humid1_icon_tabler_filled_16 (0 glyphs, lh=17px)` as a blank row.
- **Root Cause**:
  1. In `tools/fonts/humid1_ft_raster.py:221`, `load_icon_name_registry()` executed `ICON_NAME_REGISTRY = json.loads(...)`, which rebound the variable inside `humid1_ft_raster` instead of mutating the dictionary in place (`ICON_NAME_REGISTRY.clear(); ICON_NAME_REGISTRY.update(...)`). Because `humid1_generate_1bpp.py` imported `ICON_NAME_REGISTRY` by reference at module import time (when it was `{}`), `humid1_generate_1bpp.ICON_NAME_REGISTRY` remained empty (`{}`).
  2. When `resolve_charset_spec_to_range_str()` evaluated `"tabler_filled_all"` (`"scope": "all"`), `by_name_map` was empty, returning `""`.
  3. `load_plan_from_scheme_json()` then fell back to `DEFAULT_ICON_FALLBACK_RANGES.get(fam)` where `fam == "icon_tabler"`, assigning `Tabler-Regular.ttf` outline codepoints (`0xEA02,0xEA08,...`) to the `Tabler-Filled.ttf` strike. Because `Tabler-Filled.ttf` (`0xEE80..0xFA6D`) shares zero codepoints with `Tabler-Regular.ttf`, all 16 `humid1_icon_tabler_filled_10..40` strikes rasterized **0 glyphs**.
  4. Additionally, in `trace_binary_to_potrace_svg_and_rerasterize()` (`humid1_bilevel_pipelines.py:143`), `cv2.findContours(..., cv2.RETR_CCOMP, ...)` only extracted a 2-level hierarchy (outer boundary + first-level hole), which drops 3rd-level interior islands inside cutouts on complex filled icons (`Phosphor-Fill.ttf`, `Tabler-Filled.ttf`, `FontAwesome7-Solid.ttf`). Upgrading to `cv2.RETR_TREE` and rendering contours in topological tree-depth order preserves all nested cutouts and interior islands.

### 3.3 Mathematical & Literature Foundation for `v1.0.19b` Resolution-Reduction Pipelines (`PRE-19-05` & `PRE-19-06`)

Per the user's direction (*"our focus is on resolution reduction (lossy or lossless), not compression"*), the six technical papers in `tech_docs.zip` and [Clément Bœsch's SDF anti-aliasing study](https://blog.pkh.me/p/44-perfecting-anti-aliasing-on-signed-distance-functions.html) establish four complementary mathematical mechanisms for high-fidelity high-resolution-to-1-BPP resolution reduction:
1. **True sRGB-to-Linear Luminance & Optional Gamma Contrast ([Bœsch 2025](https://blog.pkh.me/p/44-perfecting-anti-aliasing-on-signed-distance-functions.html); Perry & Frisken *Saffron* p. 7)**:
   Converting non-linear sRGB coverage/RGB channels to linear light via IEC 61966-2-1 inverse companding ($C_{\text{lin}} = C/12.92$ for $C \le 0.04045$, else $((C+0.055)/1.055)^{2.4}$; $Y_{\text{lin}} = 0.2126 R_{\text{lin}} + 0.7152 G_{\text{lin}} + 0.0722 B_{\text{lin}}$) eliminates non-linear mid-tone thickening during downsampling, while an optional power factor $Y_{\text{out}} = Y_{\text{lin}}^{1/\gamma}$ (Saffron $\alpha = 1.1$) provides continuous sub-pixel stem weight tuning prior to 1-bit quantization.
2. **Multi-Channel Signed Distance Fields (`msdf`, [Chlumsky/msdfgen](https://github.com/Chlumsky/msdfgen); Qin, McCool & Kaplan *I3D 2006*; Bœsch 2025)**:
   Single-channel isotropic distance fields round sharp corners when downsampled because iso-distance contours outside a convex corner form circular arcs. Partitioning glyph contours at sharp corners ($|\Delta \theta| > 25^\circ$), assigning cyclic 3-channel $(R, G, B)$ edge colors so meeting edges at every corner share one active channel and differ in the other two, and reconstructing via $d_{\text{msdf}} = \text{median}(d_R, d_G, d_B)$ preserves sharp corners during resolution reduction from $12\times$ to $1\times$.
3. **Gradient-Normalized Smoothstep SDF Magnification/Minification (`sdf-smoothstep`, Chris Green *SIGGRAPH 2007*; [Bœsch 2025](https://blog.pkh.me/p/44-perfecting-anti-aliasing-on-signed-distance-functions.html))**:
   Downsampling a $16\times$ Euclidean Signed Distance Field onto target pixel centers and normalizing the signed distance by the local $L_2$ Jacobian gradient magnitude $w = \sqrt{(\partial_x d)^2 + (\partial_y d)^2}$ via $\text{smoothstep}(-w/2, +w/2, d)$ provides rotationally invariant edge transition reconstruction before binarization.
4. **Bi-Quadratic 9-Point Lagrange Adaptively Sampled Distance Field (`adf-biquadratic`, Perry & Frisken *Saffron SIGGRAPH Submission*) & Otsu Cumulative-Moment Thresholding (`otsu-adaptive`, Nobuyuki Otsu *IEEE SMC 1979*)**:
   Reconstructing each target pixel cell from 9 sub-cell distance samples (4 corners, 4 edge midpoints, 1 center) via a bi-quadratic Lagrange bivariate polynomial with Saffron's asymmetric body-type filter cutoffs $(-0.50, +0.625)$ and contrast power $\alpha = 1.1$ preserves delicate serifs and counter apertures, while Otsu's nonparametric between-class variance maximization $\sigma_B^2(k)$ automatically selects the optimal binarization threshold from the glyph's linear gray-level histogram.
